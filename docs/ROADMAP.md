# DojoMind AI — Product Roadmap & Vision

> Single source of truth for DojoMind's product direction, architecture, curriculum and development priorities.

---

# 1. Vision

DojoMind is being built as a universal skill-learning and training platform.

The long-term goal is not simply to teach martial arts.

DojoMind should become a place where a person can learn almost any skill that can be learned through structured understanding, demonstration, practice, feedback, assessment and progression.

Examples include:

- Martial arts
- Sports
- Musical instruments
- Singing
- Dance
- Drawing and painting
- Cooking
- Languages
- Programming
- Mathematics
- Public speaking
- Photography
- Woodworking
- Electrical skills
- Bricklaying
- Carpentry
- Sewing
- Gardening
- Meditation
- Breathing
- Fitness
- Other practical, creative, technical, physical and intellectual skills

The platform should make the learner feel like they have a structured digital dojo for developing skills.

---

# 2. Core Learning Philosophy

Every skill should follow a progressive learning loop where appropriate:

Understand
    ↓
See
    ↓
Practice
    ↓
Receive Feedback
    ↓
Reflect
    ↓
Test
    ↓
Improve
    ↓
Progress
    ↓
Master

The exact implementation can vary by skill.

For example, learning piano requires different practice mechanics from learning karate, but both can use the same underlying progression architecture.

# 6. Visual Learning

Visual learning is a core part of DojoMind.

DojoMind should support normal visual assets rather than relying only on generated diagrams.

Possible visual types:

- Real instructional photographs
- Illustrations
- Line diagrams
- Body-position diagrams
- Anatomical diagrams
- Instrument diagrams
- Chord diagrams
- Movement sequences
- Charts
- Infographics
- Video demonstrations
- Animation

Visuals should be:

- Clear
- Relevant
- Instructional
- Properly labeled
- Easy to understand
- Connected to the lesson content

For physical skills, diagrams should make important body positions, alignment, angles, movement paths and contact points understandable.

# 9. Feedback System

Feedback is one of the most important future capabilities.

Depending on the skill, feedback could come from:

- Self-assessment
- Instructor
- AI
- Audio analysis
- Image analysis
- Video analysis
- Automated tests
- Performance measurements

AI feedback must clearly distinguish:

- Observed
- Known
- Inferred
- Suggested
- Uncertain

DojoMind should never pretend that AI can reliably evaluate something it cannot actually observe.

# 10. Progress System

The learner should eventually have a persistent skill profile.

Possible information:

- Skills started
- Current level
- Lessons completed
- Practice sessions
- Assessment results
- Strengths
- Weaknesses
- Streaks
- Mastered skills
- Current goals
- Recommended next practice

Progress should eventually work across all domains.

---

# 11. AI Learning Companion

DojoMind should eventually have an AI companion that acts as a learning coach.

It should help the learner:

- Understand concepts
- Explain difficult topics
- Answer questions
- Create practice sessions
- Adapt difficulty
- Identify weaknesses
- Recommend what to practice next
- Give feedback where capabilities allow
- Encourage consistency
- Explain mistakes
- Build personalized learning plans

The AI should support the curriculum rather than replace structured learning.

---

# 12. Safety

Safety is especially important for physical and hands-on skills.

Lessons involving potential physical, mechanical, electrical, chemical or other hazards should include appropriate safety guidance.

Digital instruction should not pretend to replace qualified in-person supervision where supervision is important.

# 15. Immediate Development Priorities

## Priority 1 — Universal curriculum architecture

Refactor the current curriculum so it is genuinely skill/domain based rather than permanently tied to martial arts.

Target:

curriculum
├── martialArts
├── music
├── creative
├── practical
├── intellectual
└── mindBody

Do not duplicate the curriculum engine for every category.

## Priority 2 — Generic lesson linking

Lessons must have stable IDs.

Avoid hardcoded lesson-title checks.

Prefer stable lesson IDs and generic curriculum lookup.

The curriculum should determine which lesson is available.

The UI should not contain individual lesson-specific hardcoded checks.

## Priority 3 — Build the first complete curriculum

Complete the Karate beginner path before expanding aggressively.

Recommended order:

Understanding Stances
    ↓
Front Stance
    ↓
Back Stance
    ↓
Horse Stance
    ↓
Movement
    ↓
Basic Strikes
    ↓
Basic Blocks
    ↓
Basic Kicks

## Priority 4 — Practice engine

Move beyond reading.

Build reusable practice mechanics that different skills can use.

## Priority 5 — Progress & mastery

Connect lesson completion to real persistent progress.

Start locally if necessary, then introduce backend persistence.

## Priority 6 — AI learning companion

Introduce AI after the core curriculum and progress architecture are stable.

# 17. Expansion Principle

Every new skill should answer:

1. What does the learner need to understand?
2. What must they see or hear?
3. What must they practice?
4. How can they receive feedback?
5. How can they demonstrate competence?
6. How is improvement measured?
7. What unlocks the next level?

If a new feature only benefits one skill and cannot reasonably become reusable infrastructure, consider whether it belongs in the universal engine or in a skill-specific module.

# 19. Development Rules

1. Keep universal architecture separate from individual skill content.
2. Give curriculum items stable IDs.
3. Avoid hardcoded lesson-specific logic in UI components.
4. Reuse learning infrastructure across domains.
5. Keep specialized skill logic where specialization is genuinely necessary.
6. Use real instructional visuals where appropriate.
7. Never sacrifice clarity for visual complexity.
8. Build practice, not just reading.
9. Build measurable progress.
10. Treat safety seriously.
11. Test every major change before committing.
12. Update this roadmap when the product direction changes.
13. Mark completed roadmap items [x].
14. Do not rely on conversation memory as the project's source of truth.

---

# 20. Future Vision

The ultimate ambition is for DojoMind to become a general digital environment for learning and developing human skills.

A learner should eventually be able to say:

I want to learn piano.

or:

I want to learn karate.

or:

I want to learn drawing.

or:

I want to learn electrical engineering.

and DojoMind should be able to provide a structured path from beginner to genuine ability.

The exact curriculum, exercises, feedback mechanisms and assessment methods should adapt to the nature of the skill.

DojoMind is not limited to martial arts.

Martial arts is the first major domain through which the universal learning architecture is being developed and tested.
